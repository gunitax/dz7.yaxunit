# Тесты YAxUnit

## Под своё окружение

Этот раздел — единственное, что зависит от машины. Заполни его один раз и проверь
каждую команду на своей базе; остальной скилл ссылается сюда.

| Что | Значение в этом проекте |
| --- | --- |
| Платформа и путь к `1cv8` / `1cv8c` | 8.5.1.1529; `C:\Program Files\1cv8\8.5.1.1529\bin` (`1cv8.exe`, `1cv8c.exe`, `ibcmd.exe`) |
| Строка подключения к базе | файловая: `/F"D:\infobase\dz7.yaxunit"` |
| Пользователь 1С | `Администратор`; пароль пустой (аргумент `/P` не передавать) |
| Каталог логов и отчётов (в git не входит) | `D:\AI.DZ7\build\tests` (создаётся при первом прогоне) |

Образцы команд ниже — для Windows и файловой базы. Подставь свои значения.

**Загрузить расширение из файла `.cfe`** (движок) — два запуска `DESIGNER`, по одной
операции за запуск:

```bat
"<путь>\1cv8.exe" DESIGNER /F"<база>" /N"<пользователь>" /DisableStartupDialogs ^
  /LoadCfg "vendor\yaxunit\YAxUnit-<версия>.cfe" -Extension YAXUNIT /Out "<логи>\load-yaxunit.log"

"<путь>\1cv8.exe" DESIGNER /F"<база>" /N"<пользователь>" /DisableStartupDialogs ^
  /UpdateDBCfg -Extension YAXUNIT /Out "<логи>\update-yaxunit.log"
```

**Загрузить расширение из файлов** (расширение тестов в XML) — тоже два запуска:

```bat
"<путь>\1cv8.exe" DESIGNER /F"<база>" /N"<пользователь>" /DisableStartupDialogs ^
  /LoadConfigFromFiles "<каталог расширения>" -Extension <Имя> /Out "<логи>\load-tests.log"

"<путь>\1cv8.exe" DESIGNER /F"<база>" /N"<пользователь>" /DisableStartupDialogs ^
  /UpdateDBCfg -Extension <Имя> /Out "<логи>\update-tests.log"
```

`/LoadCfg` или `/LoadConfigFromFiles` вместе с `/UpdateDBCfg` в одном вызове платформа
отклоняет с «Ошибка в параметрах командной строки» — обновление базы всегда отдельным
запуском.

Если расширение ведётся в Конфигураторе, а не файлами, — загрузка через «Конфигурация →
Расширения конфигурации» и «Обновить конфигурацию базы данных».

**Выгрузить расширение в `.cfe`** (для сдачи и передачи):

```bat
"<путь>\1cv8.exe" DESIGNER /F"<база>" /N"<пользователь>" /DisableStartupDialogs ^
  /DumpCfg "<каталог>\<Имя>.cfe" -Extension <Имя> /Out "<логи>\dump.log"
```

**Снять безопасный режим и защиту от опасных действий** с `YAXUNIT` и расширения тестов —
после каждой загрузки: Конфигуратор загружает расширение с включёнными флагами. Либо
в Предприятии «Все функции → Стандартные → Управление расширениями конфигурации»,
либо утилитой `ibcmd` серверной платформы:

```bat
"<путь>\ibcmd.exe" config extension update --db-path="<база>" --user="<пользователь>" ^
  --name=YAXUNIT --safe-mode=no --unsafe-action-protection=no
```

`ibcmd` требует монопольного доступа к файловой базе. Если база опубликована на
веб-сервере (в этой среде — `http://localhost/dz7/`, Apache 2.4), на время команды
публикацию остановить (`Stop-Service Apache2.4`), после — запустить
(`Start-Service Apache2.4`); иначе будет «Ошибка исключительной блокировки
информационной базы».

**Запустить тесты** — тонкий клиент с конфигом:

```bat
"<путь>\1cv8c.exe" ENTERPRISE /F"<база>" /N"<пользователь>" /DisableStartupDialogs ^
  /C"RunUnitTests=<полный путь к конфигу>.json"
```

Клиент закрывается сам, если в конфиге `"closeAfterTests": true`. Итог — файлы `reportPath`
и `exitCode` из конфига, окно 1С смотреть не нужно. Человеку показать прогон —
в 1С раздел «YAxUnit», «Запустить все тесты»: те же тесты в дереве с итогом внизу формы.

Перед загрузкой закрыть клиенты 1С этой базы: открытый сеанс мешает обновлению.

## Подключение (один раз)

1. Взять официальный релиз с GitHub `bia-technologies/yaxunit`, совместимый с платформой,
   и положить `.cfe` в репозиторий вне каталога исходников: `vendor/yaxunit/`. Версию
   и sha256 файла записать в `AGENTS.md`. Файл не выгружать в XML и не править.
2. Загрузить движок, снять с него защиту (раздел выше).
3. Создать расширение тестов — отдельное от расширений продукта, исходниками рядом
   с ними. Загрузить, снять защиту.
4. Конфиги запуска: по одному на уровень и общий (раздел «Запуск»).
5. Проверка цепочки: один тест проходит, один падает на своём утверждении — отчёт
   и код результата 1. Потом проверочные тесты убрать, прогон — код 0, коммит.

Сигнатуры методов YAxUnit смотреть в исходниках того же тега (`exts/yaxunit/src` на GitHub),
не по памяти: сайт документации может расходиться с версией.

## Модуль

Тесты — общие модули расширения тестов: `Сервер` включён, `Глобальный` и `Вызов сервера`
выключены. С `Глобальный` или `Вызов сервера` YAxUnit модуль тестовым не считает и молча
пропускает. Тесты, которые читают или пишут базу, — серверные (`ДобавитьСерверныйТест`).

Уровень — тег на модуле, до набора: `ЮТТесты.Тег("Юнит")` в модуле юнит-тестов (без базы),
`ЮТТесты.Тег("Интеграция")` в модуле интеграционных (с базой).

Имя набора — `Общий модуль ИмяМодуля. Метод()`, имя теста — `Метод_Уточнение`,
представление — `Метод(). Уточнение`: имя теста читается как правило.

```bsl
Процедура ИсполняемыеСценарии() Экспорт

	ЮТТесты
		.Тег("Юнит")
		.ДобавитьТестовыйНабор("Общий модуль ИмяМодуля. Метод()")
			.ДобавитьСерверныйТест("Метод_Уточнение", "Метод(). Уточнение");

КонецПроцедуры
```

Тест видит только экспортные методы проверяемого модуля: тест лежит в другом расширении.
Проверяемое правило выносить в экспортную функцию — это нормально.

Синтаксический контроль расширения тестов отдельно от движка (Конфигуратор, проверка
модулей) пишет «Переменная не определена» на `ЮТТесты` и `ЮТест`: проверка не видит
расширение движка. В сеансе Предприятия вызов проходит — эти строки не переписывать.

На модуле интеграции — `.УдалениеТестовыхДанных()`. `.ВТранзакции()` не ставить, если
проверяемый код сам открывает транзакцию.

## Данные и проверки

Конструктор `ЮТест.Данные().КонструкторОбъекта(...)`: важные для теста поля — `Установить`,
остальные обязательные — `ФикцияОбязательныхПолей`, необязательные пустые не заполнять.
Справочную запись, без которой объект не записать, найти в базе, подставить ссылкой и не
менять; ссылку задать до фикции, иначе фикция создаст новый объект.

Созданное конструктором удаляет `УдалениеТестовыхДанных`, и объекты, и записи регистров
сведений: конструктор умеет и `РегистрыСведений.<Имя>`. Созданное проверяемым кодом
конструктор не видит: запомнить и до утверждений вызвать
`ЮТест.Данные().ДобавитьКУдалению(...)` — ссылку объекта или ключ записи регистра
`РегистрыСведений.<Имя>.СоздатьКлючЗаписи(Новый Структура("Период, <Измерение>", ...))`.
Удаление после упавшего утверждения не выполнится, и данные останутся после красного прогона.
`ДобавитьКУдалению` заменяет переданную переменную массивом: передавать копию, если
переменная нужна дальше.

Удаление идёт по ключам: запись регистра с тем же периодом и измерениями, которую
проверяемый код заменил, удалится по ключу исходной записи. Один ключ регистрировать
к удалению один раз, даже если код записывает его повторно.

Записи в таблице базы — `ЮТест.ОжидаетЧтоТаблицаБазы("Вид.Имя")` с предикатом
`ЮТест.Предикат().Реквизит("Поле").Равно(...)`. Поля результата —
`ЮТест.ОжидаетЧто(Значение).Свойство("Поле")`.

Красный прогон: заглушка проверяемого кода возвращает пустой результат, а не исключение,
и тест падает на своём утверждении. Заглушка маршрута HTTP — ответ с кодом успеха
и пустым телом по контракту (пустые массивы, а не отсутствие тела): иначе тест упадёт
на разборе ответа, а не на утверждении. Ошибка компиляции, исключение «не реализовано» — не Red:
тест не дошёл до проверки.

## Запуск

Прогон ничего не загружает: после правки расширения — загрузка и снятие защиты, потом прогон.

Конфиг уровня:

```json
{
  "filter": { "extensions": ["<расширение тестов>"], "tags": ["Юнит"] },
  "reportFormat": "jUnit",
  "reportPath": "<логи>/yaxunit/юнит.xml",
  "exitCode": "<логи>/yaxunit/юнит-exit.txt",
  "closeAfterTests": true
}
```

Общий — тот же без `tags`. Без фильтра по расширению в прогон попадают тестовые модули
других расширений. Один тест — отдельный конфиг с `"tests": ["ИмяМодуля.ИмяМетода"]`
в `filter`, общий не править.

Тег в `filter` должен совпадать с `ЮТТесты.Тег(...)` в модулях расширения. В загруженном
в этой базе расширении `СчетаМагазинаТесты` теги — `unit` (юнит-модуль) и `integration`
(интеграционный), поэтому для него в конфиге `"tags": ["unit"]`.

Итог — по отчёту, а не по одному коду: в `exitCode` 0 — тесты прошли, 1 — есть падения
(текст — `failure` в jUnit). Модуль с ошибкой компиляции YAxUnit пропускает, и код остаётся 0:
сверять число тестов в отчёте с числом зарегистрированных.
