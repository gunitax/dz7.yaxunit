---
name: make-cfe
description: Build a .cfe file of an extension by name from 1c/extensions/<name> via a disposable empty temp infobase (create base -> LoadConfigFromFiles main config -> LoadConfigFromFiles -Extension -> DumpCfg -Extension -> delete base). Output defaults to build\<name>.cfe.
---

Сборка .cfe расширения по имени. Расширение берётся из выгрузки `1c/extensions/<ИмяРасширения>/`, .cfe собирается через одноразовую пустую файловую базу: база создаётся, в неё грузится основная конфигурация, создаётся расширение, в него грузятся файлы расширения, выгружается .cfe, база удаляется. Рабочие базы и репозиторий не изменяются.

## Запуск

Скрипт: `skills\make-cfe\scripts\make-cfe.cmd <ИмяРасширения> [выход.cfe]`

- Через Bash tool только с `run_in_background: true` (полный цикл ~5-10 мин, лимит обычного вызова — 10 мин); завершение ждать через TaskOutput.
- `ИмяРасширения` обязателен и должен совпадать с папкой в `1c/extensions/` (например `ТранспортныеСредства`); имя расширения в его `Configuration.xml` (`Properties → Name`) должно быть тем же.
- Выход не задан — `build\<ИмяРасширения>.cfe` от корня репозитория; относительный путь считается от корня, `.cfe` дописывается при отсутствии.

## Что делает скрипт

1. Проверяет, что `1c\extensions\<Имя>\Configuration.xml` существует.
2. Находит последнюю платформу в `C:\Program Files\1cv8\*\bin\1cv8.exe`.
3. Удаляет старые временные базы `%TEMP%\1c-cfe-build-*` (в т.ч. от убитых по таймауту запусков).
4. `CREATEINFOBASE File=...` — пустая файловая база во `%TEMP%`.
5. `DESIGNER /LoadConfigFromFiles <корень репо>\1c` — основная конфигурация (~1,5-2 мин).
6. `DESIGNER /LoadConfigFromFiles 1c\extensions\<Имя> -Extension <Имя>` — создаёт расширение и грузит файлы (отдельный `/CreateExtension` на 8.5.1.1529 молча не работает).
7. `DESIGNER /DumpCfg <выход>.cfe -Extension <Имя>`.
8. Всегда удаляет временную базу, в том числе при ошибке; при ошибке печатает логи main/extload/dump.log.

## Проверка результата

- Успех = `exit 0` **и** .cfe существует с размером > 0. Пустой лог `/Out` — не признак успеха (платформа может упасть до начала логирования).
- Сборка идёт на свежей пустой базе без `/N /P`; `/UpdateDBCfg` не нужен.

## Ловушки

- Мгновенный exit 1 с пустым `/Out` на шаге загрузки — чаще всего битый XML в выгрузке (диагностика — скилл `make-extension`), проверен кейс: словарь метаданных `Precision`/`NonNegative` вместо формового `Digits`/`FractionDigits`/`AllowedSign` в `Form.xml`. Второй подтверждённый фактор — чужой запущенный 1cv8 в момент старта (параллельная сессия): при отсутствии процессов 1cv8 тот же прогон проходил EXIT 0; перед ретраем проверять `tasklist /fi "IMAGENAME eq 1cv8.exe"`.
- Кракозябры в эхо имени расширения — косметика захвата консоли (OEM-кодировка); проверка файлов, CreateExtension и .cfe выполняются с правильным именем.
- Батник — **только ASCII**: cmd читает .cmd в OEM-кодировке (CP866), кириллические литералы в файле превращаются в кракозябры и шаг молча падает exit 1 с пустым `/Out`. Имя расширения передаётся аргументом командной строки (Unicode) — это безопасно. Если понадобится кириллица в файле — конвертировать батник в CP866.
- Никогда не делать `taskkill` по образу 1cv8: можно убить Конфигуратор пользователя. Если Bash-таймаут убил скрипт — просто перезапустить: он сам подчистит `%TEMP%\1c-cfe-build-*` и пересоздаст базу.
- Убийство дизайнера посреди загрузки портит базу (дальше молча exit 1 с пустым логом) — лечится только пересозданием, что скрипт и делает.
- Формат выгрузки расширения и диагностику зависаний загрузки — скилл `make-extension`.
- Применение .cfe к рабочей базе этим скиллом не выполняется (см. «Запрещённые действия» в AGENTS.md) — только пользователь.
